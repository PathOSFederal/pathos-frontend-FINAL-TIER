# Day 91–93 – Resume Builder experience layer upgrade

## What changed

This pass upgrades the Builder experience layer without changing the underlying
architecture.

The Builder now feels more like a live document with attached guidance instead
of a form beside helper panels. The main changes are:

- subtle anchor-line overlays inside active sections
- more direct, document-like editing surfaces
- stronger attached-guidance cues
- more visible “alive” feedback while rewrite assistance is running

## Why it matters

Earlier slices made the Builder cohesive and trustworthy. This pass makes it
feel more immediate and easier to read in place.

Users can now see more clearly:

- which section PathOS is referring to
- where guidance is attached
- when rewrite assistance is actively working
- that they are editing a document, not filling out a detached form

## What users should expect

- active sections show attached guidance and rewrite cues more clearly
- callout-style anchor lines connect the current section to inline guidance or
  rewrite activity without shifting layout
- textareas feel lighter and more document-like while staying textarea-based
- rewrite assistance remains explicit and suggestion-only, but now looks more
  alive during the request lifecycle

## What this does not do

- no backend changes
- no rich text editor
- no layout redesign
- no chat behavior
- no hidden scoring or automatic apply

## Trust and safety posture

This pass preserves the existing PathOS trust model:

- Builder is still the primary workspace
- Review is still a handoff surface
- original text stays visible
- AI suggestions remain bounded and explicit
- apply is still user-driven
- diagnostics grounding still comes from backend-owned signals
